## Nouveaux constats

### `AUD-SEC-26` — Un marqueur « -----BEGIN » incomplet placé avant une clé privée fait sauter le vrai bloc : la clé reste en clair (Faible, sprint 15)

**Preuve.** core/src/main/java/com/nexus/security/SensitiveContentRedactor.java:403-419 replacePrivateKeyBlocks : après un « -----BEGIN  » sans suffixe, markerEnd = indexOf("-----", begin+11)+5 trouve les tirets du vrai « -----BEGIN RSA PRIVATE KEY----- » qui suit, puis cursor = markerEnd (:418) passe au-delà de son début ; le bloc n'est plus reconnu et aucun autre motif ne couvre un corps PEM. Sonde (corps factice) : masqué seul ; en clair derrière `if (line.startsWith("-----BEGIN "))` + fixture, « -----BEGIN \n », ou « -----BEGIN CERT\n ». Identique sur 510ff8ca : préexistant, non introduit par la PR #369.

**Vérification.** Rejoué indépendamment (java 21, classes de 244ab1d3, corps de clé factice) : bloc seul masqué ; précédé de `if (line.startsWith("-----BEGIN ")) {}` ou d'une ligne « -----BEGIN  » → corps en clair. Identique sur 510ff8ca (préexistant).

**Impact.** Clé privée d'une fixture de test (parseur PEM, doc) publiée en clair dans Lucene, embeddings et sorties CLI/REST/MCP.

**Action.** Si le marqueur n'est pas une clé privée, reprendre à begin + PRIVATE_KEY_BEGIN.length() (ou chercher la fin de marqueur sur la même ligne) ; test « BEGIN incomplet puis bloc RSA » ; POLICY_VERSION v10, content-v9, migration d'invalidation.

### `AUD-QUA-29` — L'assistant refuse « ^ » dans NEXUS_HOME, y compris sur la page Runtime sautée : un profil Windows contenant ^ bloque le mode Docker (installation silencieuse figée sur une MsgBox) (Faible, sprint 15)

**Preuve.** harden-windows-installer-source.ps1:113-117 ContainsUnsafeConfigChars refuse ^ ; :223-230 la page Docker vérifie aussi RuntimePage.Values[0] ; template:920 défaut %USERPROFILE%\.nexus, :972 dépôt = %USERPROFILE%, :1008 page Runtime sautée hors profil personnalisé. Or ^ est littéral dans set "…" (rendu a^b vérifié) et dans une valeur .env entre apostrophes (DotEnvQuoted). MsgBox et non SuppressibleMsgBox : /SUPPRESSMSGBOXES ne le supprime pas (test-windows-config-escaping.ps1:342). Déduit de la lecture, non rejoué.

**Vérification.** Rejoué le 12/11 sous Windows PowerShell 5.1 (repro-qua28.ps1, fonctions extraites de la source durcie) : profil « a^b » → ligne set "NEXUS_HOME=…\a^b\.nexus" correcte et exécutée sans erreur en page 850, mais ContainsUnsafeConfigChars(NEXUS_HOME) = vrai, donc refus par l'assistant. La MsgBox non supprimable est déduite de la lecture.

**Impact.** Utilisateur dont le nom de profil contient ^ (autorisé par Windows) : mode Docker bloqué avec un message sur des « chemins générés » qu'il ne peut corriger (NEXUS_HOME natif inutilisé en Docker seul, page Runtime masquée) ; installation silencieuse Docker en attente d'une boîte modale.

**Action.** Retirer ^ de ContainsUnsafeConfigChars (déjà sûr dans les deux formats) ou ne valider RuntimePage.Values[0] que si InstallNative() ; passer les MsgBox de NextButtonClick en SuppressibleMsgBox ; fixture « a^b » dans test-windows-config-escaping.ps1.
